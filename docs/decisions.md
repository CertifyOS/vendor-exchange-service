## Step 0: repository from template, pins, roles, CI (2026-10-01)

1. **Origin.** Created from the org template `CertifyOS/quarkus-base`, the same template `file-ingestion-service` started from (its initial commit is byte-for-byte the template tree). Template leftovers removed as file-ingestion did: `Dockerfile.native`, `Dockerfile.native-micro`, `Dockerfile.legacy-jar`, the Spanner config, the generic `ApplicationLivenessCheck` and its test, `src/native-test`.

2. **Pins.** Quarkus 3.33.3, JobRunr 8.8.2, Gradle wrapper 8.9, Java 21, unchanged from file-ingestion's gate. The dependency list is file-ingestion's minus the file-parsing libraries (`fastexcel-reader`, `commons-csv`, `re2j`) and minus `testcontainers:gcloud` (no Pub/Sub emulator test planned; the push handler is tested with direct HTTP).

3. **Quality gates on from the first commit.** CI runs `./gradlew check`, which includes Spotless, Checkstyle, SpotBugs, unit and integration tests. file-ingestion left the three static gates out and carries a 160-violation backlog (its findings 23, 55). Two Checkstyle rules from the template conflict with CDI and were adjusted rather than suppressed per file:
   - `VisibilityModifier`: first relaxed for `@Inject` fields, then restored to the default when the playbook (finding 23) settled on constructor injection only; `ArchitectureTest.noFieldInjection` enforces it.
   - `DesignForExtension` removed. CDI beans need overridable public methods for client proxies; the rule flags every one of them.
   `config/spotbugs/exclude.xml` first emptied (the template's filter named `com.certifyos.dal.*` classes and excluded nothing here), then given the playbook's one policy exclusion: `EI_EXPOSE_REP` and `EI_EXPOSE_REP2` off for the whole codebase, with records copying collections in compact constructors (finding 23).

4. **No `pre-push` hook.** The template's hook ran the full test suite on every push. CI is the gate; local runs are compile and lint (`make compile`, `make lint`). `commit-msg` (Conventional Commits) is kept.

5. **Role check.** `config/RoleProfileCheck` is file-ingestion's class with the package changed: exactly one of `api` or `worker` must be an active profile. `%worker` is the only profile that turns the JobRunr background server on; `%api` has no keys yet and exists so `prod,api` is a valid, explicit role.

6. **Checkstyle suppressions.** The template's suppressions named a DAL generator path and three DAL classes. Replaced with generic rules for `src/test` and `src/integrationTest` (Javadoc, static imports, visibility, `System.out`), generated sources, and non-code files.

7. **Step 0 gate.** PR #1, CI run `36853441920`: `./gradlew check` green in 5 min 1 s on the first run (Spotless, Checkstyle on three source sets, SpotBugs, `RoleProfileCheckTest` 4 of 4, `integrationTest` with no sources yet). `./gradlew quarkusBuild` produced `build/quarkus-app/quarkus-run.jar` locally. The image build was not run locally (no Docker daemon on this machine at the time); it is exercised by `make build-image` in Step 8 before the first push to Artifact Registry. One Checkstyle rule bit on the first local run: `LocalVariableName` refuses single-letter locals (`^[a-z][a-zA-Z0-9]+$`), so `catch (Exception e)` is fine (parameter) but `var e = assertThrows(...)` is not.

8. **Branch protection on `main`.** Set by API on day one: required status check `check` (strict), one approving review, code-owner review, dismiss stale reviews, conversation resolution, no force push or deletion. `file-ingestion-service` has no protection on `main` (checked, 404 on the protection endpoint), so this is a deliberate difference rather than a copy.

## Step 1: configuration and test profiles (2026-10-01)

9. **`VendorExchangeConfig` is the closed `vendor-exchange.*` mapping.** Six keys have no default (`vendor-bucket`, `egress.url`, `egress.iap-client-id`, `dal.url`, `dal.iap-client-id`, `api-layer.url`). `VendorExchangeConfigTest.everyMissingRequiredKeyIsNamed` and `unknownKeyUnderThePrefixIsRefused` prove the SmallRye-level behaviour (every missing key named in one `ConfigValidationException`; an undeclared key under the prefix refused) on a bare `SmallRyeConfigBuilder`. Quarkus applies the same validation at boot: file-ingestion observed `SRCFG00050` live for leftover `file-ingestion.role` keys (its finding 16). No Quarkus-level boot-failure test exists here; `@QuarkusTest` has no clean way to assert a failed boot without the deployment test framework. Test values live in `TestConfig.common()`, shared by both profiles, because the mapping is validated on every boot whether or not a test injects it.

10. **Swap-in keys are `Optional` and map to `${ENV:}`.** `api-layer.client-id`, `api-layer.client-secret`, `pubsub.push-service-account`, `pubsub.push-audience` resolve to an empty string when the environment variable is unset, and SmallRye reads an empty value as `Optional.empty()`. Asserted twice: on the mapping alone (`optionalKeysAreAbsentWhenUnsetOrEmpty`) and through the real `application.properties` under the api profile (`ApiRoleBootIT.swapInKeysResolveToAbsentThroughTheEmptyDefault`). The api-layer client secret stays a plain environment variable until Step 8 decides between a `${sm//...}` reference (which fails the boot when the secret has no version) and a placeholder version.

11. **JobRunr retries come from the mapping.** `quarkus.jobrunr.jobs.default-number-of-retries=${vendor-exchange.job-retries}` with `vendor-exchange.job-retries=${JOB_RETRIES:8}` declared as a property, because a `@WithDefault` on the mapping is not a property value another expression can expand. Same pattern for every default the deployment may override.

12. **Dashboard on the worker profile, off in the worker test profile.** `%worker.quarkus.jobrunr.dashboard.enabled=true` on port 8000 for the real VM (reached through an IAP SSH tunnel; no firewall rule). `WorkerTestProfile` overrides it to `false` so a test JVM never binds the port. `WorkerRoleBootIT` asserts both flags and waits for the server's heartbeat row through `StorageProvider` as the proof the worker role runs. On the api role, `ApiRoleBootIT.jobRunrServerDoesNotRunOnTheApiRole` is behavioural too: the `BackgroundJobServer` bean exists on both roles (the extension decides start or no-start from the flag at runtime), so the test asserts `isRunning() == false` and an empty server list held across more than one poll interval.

13. **Telemetry exporters off at the base level.** `quarkus.otel.sdk.disabled=true` and `quarkus.log.sentry.enabled=false` until Step 7, so no boot logs connection errors against `localhost:4317`. `quarkus.log.console.json.enabled` is the current key (the bare `quarkus.log.console.json` file-ingestion uses is the deprecated spelling); JSON off under `%dev` and `%test`.

14. **HTTP policy declared now, endpoints later.** `/q/*` permit, `/internal/*` permit (the push filter does its own 401 in Step 5), `/vendor-exports/*` authenticated. `ApiRoleBootIT.operatorPathsRequireAuthentication` gets a 401 on `/vendor-exports/schedules` with the OIDC tenant disabled and no resource behind the path, which is the HTTP-layer policy working on its own. This is the coverage file-ingestion recorded as missing (its finding 20); it holds here because the assertion needs no token at all.

15. **Step 1 gate.** CI run `36855962179` green in 2 min 36 s: unit 10 of 10 (`RoleProfileCheckTest` 4, `VendorExchangeConfigTest` 6), integration 7 of 7 (`ApiRoleBootIT` 5, `WorkerRoleBootIT` 2) against Testcontainers `mongo:7.0`. Both roles boot from the same `application.properties`; the empty-means-absent rule, the 401 on `/vendor-exports/*`, and the worker heartbeat row are all proven by a running Quarkus, not by inspection.

## Cross-check of Steps 0 and 1 (2026-10-01, independent review pass)

16. **JobRunr collection names.** JobRunr 8.8.2 with no `table-prefix` creates `jobs`, `recurring_jobs`, `background_job_servers`, `metadata`, `migrations`, with no `jobrunr_` prefix (file-ingestion finding 72, observed live). The design doc and the plan name them `jobrunr_*`. Rather than correct both documents, `quarkus.jobrunr.database.table-prefix=jobrunr_` is set: `StorageProviderUtils.elementPrefixer` concatenates prefix and name directly (checked in the 8.8.2 bytecode), so the collections come out as `jobrunr_jobs` and so on, matching the documents and marking ownership beside `vendor_export_*` in the same database. `WorkerRoleBootIT.jobRunrCollectionsCarryThePrefixTheDesignDocNames` lists the database's collections after the heartbeat and asserts the prefixed names and the absence of unprefixed ones.

17. **`quarkus.shutdown.delay-enabled` is build-time fixed** (`ShutdownBuildTimeConfig.delayEnabled`), so `${SHUTDOWN_DELAY_ENABLED:true}` was resolved at `quarkusBuild` and the environment variable did nothing. Now a literal `true`; `quarkus.shutdown.delay` stays the runtime knob and `SHUTDOWN_DELAY_ENABLED` left `.env.example`.

18. **`google-auth-library-oauth2-http` declared.** Step 5 imports `com.google.auth.oauth2.TokenVerifier` directly; it was only on the classpath transitively through the Google Cloud clients. Declared at 1.30.0; Gradle resolves it to 1.42.1 because `google-cloud-storage` 2.45.0 requires that (checked with `./gradlew dependencies`), and `TokenVerifier` exists in both.

19. **Egress internal hostname and IAP lookup.** `.env.example` now carries `https://practitioner-egress-service.internal.certifyos.com` (from `core-dal-egress-practitioner-async/infrastructure`) and the two-step `gcloud` lookup for the egress backend's IAP client id; the DAL and api-layer hostnames were confirmed against api-layer's Terraform (`https://api-service.internal.certifyos.com`).

20. **Every Quarkus key in `application.properties` checked against its extension jar, not memory**: JobRunr `background-job-server.enabled`, `dashboard.enabled`, `dashboard.port`, `worker-count`, `poll-interval-in-seconds`, `jobs.default-number-of-retries`, `database.database-name`, `database.table-prefix` are all `JobRunrRuntimeConfiguration` (runtime), and the build-time `included` flags default to true, so one image serves both roles by profile. `quarkus.log.sentry.enabled` (SentryConfig), `quarkus.log.console.json.enabled` (JsonLogConfig; the bare key is the deprecated `enable()`), `quarkus.otel.sdk.disabled`, the OIDC, MongoDB and Keycloak Dev Services keys all exist at 3.33.3. The CI boot logs captured in the test reports show zero WARN or ERROR lines for either profile.

21. **One Mongo container per test profile.** `QuarkusTestResourceLifecycleManager` runs in a classloader per `@TestProfile`, so `MongoResource`'s static container is per profile: the CI log shows `mongo:7.0` starting once for `ApiRoleBootIT` and once for `WorkerRoleBootIT`, about one second each. Acceptable; it also means an empty server list on the api role cannot be a leftover from the worker role.

22. **Still owed from the Step 0 gate:** the local `docker build --platform linux/amd64` of `Dockerfile.jvm`. The Docker daemon is not running on this machine; the paths in the Dockerfile match the fast-jar layout (`build/quarkus-app/{lib,app,quarkus,*.jar}`, checked). First real build is `make build-image` in Step 8.

## Playbook alignment (2026-10-01): "New Service Playbook: Lessons from api-layer and DAL"

23. **The playbook's checklist is the day-one standard from here on.** Read in full (81 findings, six areas, a checklist of 46 items). Everything a single repository controls is now enforced mechanically; what it cannot settle alone is an ask. Applied in one commit on top of Steps 0 and 1:
    - **Constructor injection only.** `ArchitectureTest.noFieldInjection` (ArchUnit) fails on any `@Inject` field. Quarkus injects a bean's single constructor without an annotation. The Checkstyle exemption from finding 3 is gone.
    - **Module layout enforced.** `ArchitectureTest`: shared packages (`config`, `persistence`, `audit`, `auth`, `clients`, `metrics`) never depend on `export..`; slices free of cycles; one logger API (JBoss, no SLF4J or `java.util.logging`); no `new ObjectMapper()`; no `Executors.new*`; no `Thread.sleep`; no `JsonNode` in `api`, `events`, `clients`. Rules match no class yet and use `allowEmptyShould(true)` so they bite the moment a class appears.
    - **Size and naming caps in Checkstyle.** `FileLength` 500 (main) and 1,000 (test) as two ids with mirrored suppressions; `ParameterNumber` 7 on constructors; `BanTicketKeys` (no `CP-nnnn` in main source); `DisabledNeedsTicket` (`@Disabled` must carry a ticket); JBoss logger with `{}` placeholders refused.
    - **Build hygiene.** `gradle/libs.versions.toml` is the only place a version lives (`build.gradle` references `libs.*`, plugins via `alias`); `mavenLocal()` removed from both Gradle files; a resolution rule throws on any `-SNAPSHOT`; `gradle.properties` holds JVM args only; `renovate.json` with digest pinning and a Quarkus plus JobRunr group.
    - **Pins by digest and SHA.** `Dockerfile.jvm` base image by digest (`ubi9/openjdk-21:1.21`), Testcontainers `mongo:7.0` by digest through `DockerImageName.asCompatibleSubstituteFor("mongo")`, every GitHub action by commit SHA with the tag as a comment, gitleaks container by digest (v8.30.1).
    - **Secret scanning.** CI job `secrets` runs gitleaks over the full history (`fetch-depth: 0`); the official action needs a paid licence for organisation repositories, so the container is used directly. `githooks/pre-commit` runs `gitleaks git --pre-commit --staged` when gitleaks is installed and says so when it is not.
    - **Deny by default.** `quarkus.http.auth.permission.deny-all` on `/*` with `policy=deny`; `/q/*` and `/internal/*` permitted (the push filter guards the latter); operator endpoints under `/v1/*` authenticated. `ApiRoleBootIT.unknownPathsAreDeniedByDefault` gets 401 on an undeclared path.
    - **Versioned paths.** Operator endpoints move under `/v1/` from day one (`/v1/vendor-exports/...`); the design doc's unversioned paths are a doc follow-up. `/internal/...` stays unversioned: it is an infrastructure endpoint whose URL is the Pub/Sub audience.
    - **Readiness on a real dependency.** `quarkus.mongodb.health.enabled=true` (file-ingestion had it off); `/q/health/ready` pings Mongo and `ApiRoleBootIT.readinessReportsMongo` asserts the check is present. The load balancer and instance groups keep using `/q/health/live`, so a database blip never replaces a VM.
    - **No infrastructure default in the jar.** `quarkus.mongodb.connection-string=${MONGODB_URI}` lost its `localhost` default; tests set it from the Testcontainers resource, local runs from `.env`.
    - **Trace sampling set now, not later.** `parentbased_traceidratio` at 0.1 beside the still-disabled SDK, so Step 7 cannot forget it.
    - **Resilience library on the classpath.** `quarkus-smallrye-fault-tolerance` added for Step 6's client policy (timeouts, jittered retry on idempotent errors, circuit breaker, bulkhead).
    - **Repository shape.** `AGENTS.md` (one hand-written guidance file, every rule tied to the lint or file that enforces it), `CLAUDE.md` as a one-line pointer, `docs/adr/` with ADR 0001 (roles by profile), 0002 (JobRunr and the prefix), 0003 (this alignment). `HANDOFF.md` will live under `docs/`, not the root. Makefile reduced to `bootstrap`, `dev`, `fmt`, `lint`, `compile`, `test`, `check`, `build`.

24. **Playbook items this repository cannot settle alone, recorded as asks:** a shared Gradle convention plugin across Quarkus services; Renovate enabled on the organisation (the config file is in place); Workload Identity Federation so CI, not a laptop, pushes images and runs the deploy (the applying account cannot create the IAM binding, file-ingestion finding 54); a reusable deploy workflow with the environment as an input and protection rules, which depends on that identity.

25. **Playbook items that change later steps, folded into the plan:** error bodies are RFC 9457 `application/problem+json` with a stable `code`, rendered only by global exception mappers (Step 5; `ApiError` is gone from the plan); every endpoint carries an explicit security annotation and an ArchUnit rule fails on one that does not (Step 5); downstream status codes are carried through one typed client-error mapper and no exception text reaches a client (Steps 5 and 6); per-client timeouts with connect at or under 2 s, jittered retries on idempotent errors only, circuit breaker and bulkhead (Step 6); a limit on every list query and keyset cursors for the read endpoints (Steps 2 and 5); a committed OpenAPI contract with a drift check and a breaking-change gate (`oasdiff`) in CI (Step 5); a `version` field on batches as well as schedules, with compare-and-set on every update (Step 2); logs carry ids and counts only, MDC set once in a request filter and once per job (Step 7); job stubs name the behaviour they wait for, never a ticket key.

26. **Two playbook items weighed and kept as the design has them.** Boot-time index creation instead of a separate migration job: the collections are new and empty, identical `createIndex` calls are idempotent, and the plan already says any index added after go-live is built out of band first. Two integration-test profiles instead of one: the two roles differ in what boots, and the playbook's objection is to 35 profiles forcing restarts, not to two.

## Step 2: persistence foundation (2026-10-01)

27. **Selection criteria are stored as a list of clauses, not the API's object keyed by field.** The design's wire shape is `{ "data.delegationStatus": { "in": [...] } }`; a field name with a dot as a BSON key is a trap for every later `$set`, projection and query path. Stored as `[{ field, op, values }]` through the typed `SelectionCriteria` record (`Clause(field, operator, values)` with `EQ`, `IN`, `GTE`, `LTE`; single-value operators take exactly one value). The API layer (Step 5) maps between the two shapes. `SelectionCriteriaTest.roundTripsThroughBsonAsAListOfClauses` asserts the field is a value.

28. **`version` on batches too, and every write bumps it.** The design puts `version` on schedules and compare-and-sets batch transitions on `state`. The playbook asks for a version token on every mutable document, so `ExportBatch` carries `version` (1 on insert) and both `ExportBatchRepository.transition` and `updateInState` add `$inc version` beside the state filter. `ScheduleRepository.advance` and `update` compare-and-set on `version`. `ExportBatchRepositoryIT.transitionIsCompareAndSetOnState` and `ScheduleRepositoryIT.advanceIsCompareAndSetOnVersion` prove the stale writer gets `false` and the version is 2.

29. **`transition` refuses an edge the state machine does not have.** `BatchState.canTransitionTo` encodes the design's graph (`FAILED` may go back to `SCHEDULED` or `NPIS_SELECTED` for an operator retry; `EMPTY` and `SUPERSEDED` are terminal; `DELIVERED` only to `SUPERSEDED`). A job asking for an unknown edge gets `IllegalArgumentException` before any write, so a coding mistake cannot corrupt a row. `BatchState.reconcilable()` is `SCHEDULED`, `NPIS_SELECTED`, `EGRESS_COMPLETED`: a batch waiting in `EGRESS_REQUESTED` belongs to the deadline check, not the reconciler.

30. **NPI rows are upserted with `$setOnInsert` in unordered bulk writes of 500.** A retried page is a no-op (`ExportNpiRepositoryIT.repeatedPageIsANoOpAndCountsStayExact`: 1,200 rows, then the same 1,200 again inserts 0, then an overlapping 200 inserts 100) and an existing row is never rewritten (`existingRowIsNeverRewritten`). Reads are keyset paged on `npi` with a limit (`listIsKeysetPagedByNpi`).

31. **Duplicate-key translation.** `Documents.isDuplicateKey` recognises both `MongoWriteException` and `MongoBulkWriteException` with the `DUPLICATE_KEY` category; repositories throw the typed `AlreadyExistsException(collection, key)` and let anything else propagate. Inside a transaction the driver reports a unique-index violation with no transient label, so `withTransaction` does not retry it and the caller sees it (file-ingestion finding 24).

32. **Indexes.** All of the design's plus two: `(tenantId, vendor, occurredAt)` on events for schedule-level audit reads, and a partial unique index on `detail.messageId` where `type = EXPORT_EVENT_RECEIVED` for the handler's idempotency. The `egress.correlationId` index is partial on existence, so batches before the egress request do not share a null key. `MongoIndexesIT` asserts every index by name, key, uniqueness and partial filter, and that `createAll()` twice is a no-op. Index options never change in place (MongoDB refuses with `IndexOptionsConflict`); a changed index is a new name.

33. **`Ids` refuses what the design refuses.** Tenant ids with underscores (the vendor filename uses underscores as separators), sequences outside 1 to 999, attempts under 1, NPIs that are not ten digits. `batchIdOf(correlationId)` strips the `-r<attempt>` suffix for the event handler. Event ids are `ev-<uuid v7>`; `IdsTest` asserts version 7, the prefix, and that 1,000 ids sort in creation order.

34. **Constructor injection everywhere.** `Collections`, `Transactions`, `MongoIndexes` and the three repositories take their dependencies through a single public constructor; Quarkus injects it without `@Inject`, and `ArchitectureTest.noFieldInjection` now has classes to check. `MongoIndexes.createAll()` is public so a test can call it without a boot.
