## Step 0: repository from template, pins, roles, CI (2026-10-01)

1. **Origin.** Created from the org template `CertifyOS/quarkus-base`, the same template `file-ingestion-service` started from (its initial commit is byte-for-byte the template tree). Template leftovers removed as file-ingestion did: `Dockerfile.native`, `Dockerfile.native-micro`, `Dockerfile.legacy-jar`, the Spanner config, the generic `ApplicationLivenessCheck` and its test, `src/native-test`.

2. **Pins.** Quarkus 3.33.3, JobRunr 8.8.2, Gradle wrapper 8.9, Java 21, unchanged from file-ingestion's gate. The dependency list is file-ingestion's minus the file-parsing libraries (`fastexcel-reader`, `commons-csv`, `re2j`) and minus `testcontainers:gcloud` (no Pub/Sub emulator test planned; the push handler is tested with direct HTTP).

3. **Quality gates on from the first commit.** CI runs `./gradlew check`, which includes Spotless, Checkstyle, SpotBugs, unit and integration tests. file-ingestion left the three static gates out and carries a 160-violation backlog (its findings 23, 55). Two Checkstyle rules from the template conflict with CDI and were adjusted rather than suppressed per file:
   - `VisibilityModifier`: first relaxed for `@Inject` fields, then restored to the default when the playbook (finding 23) settled on constructor injection only; `ArchitectureTest.noFieldInjection` enforces it.
   - `DesignForExtension` removed. CDI beans need overridable public methods for client proxies; the rule flags every one of them.
   `config/spotbugs/exclude.xml` first emptied (the template's filter named `com.certifyos.dal.*` classes and excluded nothing here), then given the playbook's one policy exclusion: `EI_EXPOSE_REP` and `EI_EXPOSE_REP2` off for the whole codebase, with records copying collections in compact constructors (finding 23).

4. **No `pre-push` hook.** The template's hook ran the full test suite on every push. CI is the gate; local runs are compile and lint (`make compile`, `make lint`). `commit-msg` (Conventional Commits) is kept.

5. **Role check.** `config/RoleProfileCheck` is file-ingestion's class with the package changed: exactly one of `api` or `worker` must be an active profile. `%worker` is the only profile that turns the JobRunr background server on; `%api` has no keys yet and exists so `prod,api` is a valid, explicit role.

6. **Checkstyle suppressions.** The template's suppressions named a DAL generator path and three DAL classes. Replaced with generic rules for `src/test` and `src/integrationTest` (Javadoc, static imports, visibility, `System.out`), generated sources, and non-code files.

7. **Step 0 gate.** PR #1, CI run `36853441920`: `./gradlew check` green in 5 min 1 s on the first run (Spotless, Checkstyle on three source sets, SpotBugs, `RoleProfileCheckTest` 4 of 4, `integrationTest` with no sources yet). `./gradlew quarkusBuild` produced `build/quarkus-app/quarkus-run.jar` locally. The image build was not run locally (no Docker daemon on this machine at the time); it is exercised by `make build-image` in Step 8 before the first push to Artifact Registry. One Checkstyle rule bit on the first local run: `LocalVariableName` refuses single-letter locals (`^[a-z][a-zA-Z0-9]+$`), so `catch (Exception e)` is fine (parameter) but `var e = assertThrows(...)` is not.

8. **Branch protection on `main`.** Set by API on day one: required status check `check` (strict), one approving review, code-owner review, dismiss stale reviews, conversation resolution, no force push or deletion. `file-ingestion-service` has no protection on `main` (checked, 404 on the protection endpoint), so this is a deliberate difference rather than a copy.

## Playbook alignment (2026-10-01): "New Service Playbook: Lessons from api-layer and DAL"

23. **The playbook's checklist is the day-one standard from here on.** Read in full (81 findings, six areas, a checklist of 46 items). Everything a single repository controls is now enforced mechanically; what it cannot settle alone is an ask. Applied in one commit on top of Steps 0 and 1:
    - **Constructor injection only.** `ArchitectureTest.noFieldInjection` (ArchUnit) fails on any `@Inject` field. Quarkus injects a bean's single constructor without an annotation. The Checkstyle exemption from finding 3 is gone.

Rules match no class yet and use `allowEmptyShould(true)` so they bite the moment a class appears.
    - **Size and naming caps in Checkstyle.** `FileLength` 500 (main) and 1,000 (test) as two ids with mirrored suppressions; `ParameterNumber` 7 on constructors; `BanTicketKeys` (no `CP-nnnn` in main source); `DisabledNeedsTicket` (`@Disabled` must carry a ticket); JBoss logger with `{}` placeholders refused.

The load balancer and instance groups keep using `/q/health/live`, so a database blip never replaces a VM.

    - **Repository shape.** `AGENTS.md` (one hand-written guidance file, every rule tied to the lint or file that enforces it), `CLAUDE.md` as a one-line pointer, `docs/adr/` with ADR 0001 (roles by profile), 0002 (JobRunr and the prefix), 0003 (this alignment). `HANDOFF.md` will live under `docs/`, not the root. Makefile reduced to `bootstrap`, `dev`, `fmt`, `lint`, `compile`, `test`, `check`, `build`.

## Step 2: persistence foundation (2026-10-01)

27. **Selection criteria are stored as a list of clauses, not the API's object keyed by field.** The design's wire shape is `{ "data.delegationStatus": { "in": [...] } }`; a field name with a dot as a BSON key is a trap for every later `$set`, projection and query path. Stored as `[{ field, op, values }]` through the typed `SelectionCriteria` record (`Clause(field, operator, values)` with `EQ`, `IN`, `GTE`, `LTE`; single-value operators take exactly one value). The API layer (Step 5) maps between the two shapes. `SelectionCriteriaTest.roundTripsThroughBsonAsAListOfClauses` asserts the field is a value.

28. **`version` on batches too, and every write bumps it.** The design puts `version` on schedules and compare-and-sets batch transitions on `state`. The playbook asks for a version token on every mutable document, so `ExportBatch` carries `version` (1 on insert) and both `ExportBatchRepository.transition` and `updateInState` add `$inc version` beside the state filter. `ScheduleRepository.advance` and `update` compare-and-set on `version`. `ExportBatchRepositoryIT.transitionIsCompareAndSetOnState` and `ScheduleRepositoryIT.advanceIsCompareAndSetOnVersion` prove the stale writer gets `false` and the version is 2.

29. **`transition` refuses an edge the state machine does not have.** `BatchState.canTransitionTo` encodes the design's graph (`FAILED` may go back to `SCHEDULED` or `NPIS_SELECTED` for an operator retry; `EMPTY` and `SUPERSEDED` are terminal; `DELIVERED` only to `SUPERSEDED`). A job asking for an unknown edge gets `IllegalArgumentException` before any write, so a coding mistake cannot corrupt a row. `BatchState.reconcilable()` is `SCHEDULED`, `NPIS_SELECTED`, `EGRESS_COMPLETED`: a batch waiting in `EGRESS_REQUESTED` belongs to the deadline check, not the reconciler.

30. **NPI rows are upserted with `$setOnInsert` in unordered bulk writes of 500.** A retried page is a no-op (`ExportNpiRepositoryIT.repeatedPageIsANoOpAndCountsStayExact`: 1,200 rows, then the same 1,200 again inserts 0, then an overlapping 200 inserts 100) and an existing row is never rewritten (`existingRowIsNeverRewritten`). Reads are keyset paged on `npi` with a limit (`listIsKeysetPagedByNpi`).

31. **Duplicate-key translation.** `Documents.isDuplicateKey` recognises both `MongoWriteException` and `MongoBulkWriteException` with the `DUPLICATE_KEY` category; repositories throw the typed `AlreadyExistsException(collection, key)` and let anything else propagate. Inside a transaction the driver reports a unique-index violation with no transient label, so `withTransaction` does not retry it and the caller sees it (file-ingestion finding 24).

32. **Indexes.** All of the design's plus two: `(tenantId, vendor, occurredAt)` on events for schedule-level audit reads, and a partial unique index on `detail.messageId` where `type = EXPORT_EVENT_RECEIVED` for the handler's idempotency. The `egress.correlationId` index is partial on existence, so batches before the egress request do not share a null key. `MongoIndexesIT` asserts every index by name, key, uniqueness and partial filter, and that `createAll()` twice is a no-op. Index options never change in place (MongoDB refuses with `IndexOptionsConflict`); a changed index is a new name.

33. **`Ids` refuses what the design refuses.** Tenant ids with underscores (the vendor filename uses underscores as separators), sequences outside 1 to 999, attempts under 1, NPIs that are not ten digits. `batchIdOf(correlationId)` strips the `-r<attempt>` suffix for the event handler. Event ids are `ev-<uuid v7>`; `IdsTest` asserts version 7, the prefix, and that 1,000 ids sort in creation order.

34. **Constructor injection everywhere.** `Collections`, `Transactions`, `MongoIndexes` and the three repositories take their dependencies through a single public constructor; Quarkus injects it without `@Inject`, and `ArchitectureTest.noFieldInjection` now has classes to check. `MongoIndexes.createAll()` is public so a test can call it without a boot.

35. **In-memory round trips read `Instant`, Mongo round trips read `Date`.** `Document.append(key, instant)` keeps the `Instant` until the driver encodes it; `doc.getDate()` on such a document throws `ClassCastException`, which is what the three unit round-trip tests caught on CI (first failure of the branch). `Documents.instant` now accepts both. The integration tests never saw it because every document they read came back through the driver.

36. **Step 2 gate.** CI run `36861943602` green in 2 min 54 s: unit 38 of 38 (`RoleProfileCheckTest` 4, `VendorExchangeConfigTest` 6, `ArchitectureTest` 8, `IdsTest` 6, `BatchStateTest` 4, `SelectionCriteriaTest` 3, `ScheduleTest` 3, `ExportBatchTest` 4), integration 33 of 33 (`ApiRoleBootIT` 8, `WorkerRoleBootIT` 3, `MongoIndexesIT` 5, `TransactionsIT` 2, `ScheduleRepositoryIT` 5, `ExportBatchRepositoryIT` 7, `ExportNpiRepositoryIT` 3) against Testcontainers MongoDB 7 pinned by digest. The playbook commit before it (run `36860075710`) was green too: ArchUnit rules, Checkstyle caps, gitleaks and the deny-by-default policy all passed on their first run.

## Step 3: audit trail (2026-10-05)

37. **The 24 event types carry a scope.** `AuditEventType.Scope` is `SCHEDULE` (tenant and vendor, never a batch id), `BATCH` (tenant, vendor and batch id required) or `SERVICE` (`EXPORT_TICK_COMPLETED`, `EXPORT_EVENT_REJECTED`: a tick has no tenant, a rejected message may match no batch). The `AuditEvent` compact constructor enforces the rule per scope, so a mis-built event fails at construction, not in a query months later. `AuditEventTest.catalogueHasTheDesignsTwentyFourTypes` pins the count.

38. **Three write paths, one per commit rule in the design.** `write(session, event)` commits with the transition; `write(event)` is a standalone fact; `writeIdempotent(event)` is a standalone fact that returns `false` on a duplicate key instead of throwing, for `EXPORT_EVENT_RECEIVED` on `detail.messageId` under the partial unique index from Step 2. `AuditRepositoryIT` proves the event rolls back with a crashed transition, commits with a successful one, is recorded once per message id, and that another type carrying the same `messageId` is not blocked (the index is partial on type).

39. **`detail` stays a map, deliberately.** The playbook bans `Map<String, Object>` in contracts; the audit detail is the per-type payload the design's table lists, an opaque record of ids and counts that is never deserialised into a contract. It is copied on construction into an unmodifiable map, null values are dropped, and `ArchitectureTest.typedContracts` keeps the ban on the `api`, `events` and `clients` packages where it matters.

40. **Actors live in one place.** `Actors.SYSTEM` (`system:vendor-export`) and `Actors.EGRESS_EVENT` (`system:egress-event`); `ScheduleRepository.advance` now writes `Actors.SYSTEM` as `updatedBy` instead of its own copy of the string. `export.schedule` depending on `audit` is allowed by the layout rule; the reverse is not.

41. **Complexity cap met by splitting, not suppressing.** The envelope's compact constructor hit Checkstyle's `CyclomaticComplexity` of 10 (13); validation moved into two small static methods. First time the cap bit; it will keep biting on validators, and splitting is the answer every time.

42. **Step 3 gate.** CI run `37256675592` green in 2 min 54 s: unit 43 of 43 (`AuditEventTest` adds 5), integration 37 of 37 (`AuditRepositoryIT` adds 4). Green on the first push.

## Step 4: JobRunr wiring (2026-10-05)

43. **Every batch job starts with the same precheck.** `BatchJobSupport.loadExpecting(job, batchId, expectedState)` honours the kill switch, loads the row and compares the state; any mismatch is a logged no-op. Four job beans (`SelectJob`, `RequestEgressJob`, `DeadlineCheckJob`, `FinishJob`) run the precheck and then throw `UnsupportedOperationException` with a plain-words message until their bodies arrive; under Checkstyle's `BanTicketKeys` a stub names the behaviour it waits for, never a ticket. `BatchJobSupportTest` covers the four branches with a stubbed config and repository.

44. **Jobs are enqueued through one bean with deterministic ids, in JobRunr's `JobRequest` form.** `JobEnqueuer` builds `JobIds.of(job, batchId, attempt)` with `nameUUIDFromBytes` and calls `JobRequestScheduler.enqueue(id, new SelectJobRequest(batchId, attempt))`; each job bean implements `JobRequestHandler<ItsRequest>` and its `run(request)` carries `@Job(name = "select %0")`. The request is a record JobRunr serialises as JSON, its handler is resolved from CDI when the job runs, and no lambda is analysed (finding 51 says why that matters). A second enqueue with the same id returns the same id and runs nothing extra (`JobRunrGateIT.exhaustedRetriesMarkTheBatchFailedWithItsAuditEvent`).

45. **The final-failure filter is an apply-state filter that reads the job's terminal state.** JobRunr's `RetryFilter` is an elect-state filter: while retries remain it turns a `FailedState` into a `ScheduledState` before anything is applied. By the time `BatchFinalFailureFilter.onStateApplied` runs, a job whose state is still `FAILED` has no retry left. The filter maps the job class to `FailedStep` (`SelectJob` to `SELECT`, the three egress-side jobs to `EGRESS`), reads the batch id from the request record (the job's single parameter), and in one transaction moves the batch to `FAILED` with `failedStep` and `lastError` and writes `EXPORT_BATCH_FAILED` with `jobAttempts`. A failure inside the filter is logged, never rethrown: the job state is already saved and the reconciler is the backstop. Registered through a `StartupEvent` observer with `@Priority(APPLICATION)` beside the extension's `RetryFilter` (file-ingestion findings 5 and 10).

46. **Recurring jobs registered on the worker role at startup, idempotent by id.** `RecurringJobs` registers `vendor-export-tick` (`0 6 * * *`) and `vendor-export-reconciler` (`0 * * * *`) through `scheduleRecurrently` with the IoC form; `JobRunrGateIT.bothRecurringJobsAreRegisteredExactlyOnce` reads them back with their cron. The api role skips registration (a storage write it has no reason to make), but the job beans exist on both roles so the manual tick endpoint can call `TickJob.run()` inline.

47. **Tick and reconciler bodies are the query plus the fact; the per-row work is the next subtask's.** `TickJob.run()` runs `findDue(now, 1000)` and writes `EXPORT_TICK_COMPLETED` with `tickId`, `schedulesDue`, `batchesCreated` (empty until the transaction per due row arrives), `skippedAlreadyExists` and `durationMs`, returning the design's `TickResult`. `ReconcilerJob.run()` runs `findStale(reconcilable, now - staleMinutes, 500)` and logs each stuck row. `TickAndReconcilerIT` proves the due schedule is counted and the fact written, and that an old `SCHEDULED` row is stale while a fresh one and an `EGRESS_REQUESTED` one are not.

48. **Time is injected.** `Clocks` produces one `Clock.systemUTC()`; jobs and the filter take `Clock` in their constructor and never call `Instant.now()`, so a later test can pin time.

49. **Test profile sets `vendor-exchange.job-retries=1`.** Production retries 8 times with JobRunr's 3^n-second backoff, which is hours; one retry makes a stub reach `FAILED` in about 3 seconds. The gate's flaky job carries `@Job(retries = 2)` of its own. SpotBugs caught two `String.getBytes()` calls without a charset in the gate test; `StandardCharsets.UTF_8` everywhere.

50. **Recurring jobs are `@Recurring` methods, not `scheduleRecurrently` lambdas.** The first worker boot on CI failed inside `JobScheduler.scheduleRecurrently(id, cron, job -> job.run())`: JobRunr's `JobDetailsBuilder` threw `IllegalStateException: Can not find variable 2 in stack` analysing the no-capture IoC lambda written inside a CDI bean (the lambda's synthetic method is in a class Quarkus transforms, and the analyser reads slots that are not there).
